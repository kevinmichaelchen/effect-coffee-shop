# Lint

- Oxlint policy lives in `packages/tooling/oxlint.profiles.ts`: a `backend` profile (adds the `@mpsuesser/oxlint-plugin-effect` house style) and a `ui` profile. Every workspace's `lint` script points at one of them; there are no per-workspace Oxlint configs.
- Lint runs through `effect-tsgo --tsrs-lint oxlint` from the official [`@effect/tsgo`](https://github.com/Effect-TS/tsgo), which loads Oxlint with an Effect-patched native binding and runs every type-aware rule, including the Effect language-service rules (`effecttsgo/*`, the strict preset plus selected opt-ins), on the Effect-patched tsrs linter instead of `tsgolint`. Oxlint and `tsrs` are pinned to versions in its "Supported Package Versions" table.
- Both profiles enable the `correctness`, `suspicious` and `perf` categories and the unsafe-TypeScript rules (`no-explicit-any`, `no-unsafe-*`, `no-unsafe-type-assertion`, `strict-boolean-expressions`, ...). Lint is type-aware and type-checks; since tsrs 0.23 that check covers the whole program of each tsconfig Oxlint's files map to, so lint can fail on a type error in a file it does not lint. Typecheck is `tsrs --noEmit`.
- `backend` runs every rule of `@mpsuesser/oxlint-plugin-effect` (which vendors [dmmulroy/anti-slop](https://github.com/dmmulroy/anti-slop)'s generic rules). `ui` takes only its type-assertion rules (`no-chained-type-assertions`, `no-known-value-widening`, `no-widen-then-assert`, `require-safety-comment-for-type-assertion`, `no-reflect-*`) plus `no-console` outside `scripts/`; the profile comment explains which ones stay backend-only and why.
- No rule limits file or function size. Deep modules are preferred; Fallow health reports complexity.
- Custom Go rules live in `packages/tooling/.lintcn` (backend) and `apps/ui/.lintcn` (UI). They need Go 1.26 (`GOTOOLCHAIN=auto`). They enforce AGENTS.md bans that Oxlint cannot express, including `no-in-operator` and `no-instanceof`. To run a rule's Go tests, symlink `.lintcn/.tsgolint` to the checkout lintcn caches in `~/.cache/lintcn/tsgolint/<sha>` (gitignored), then `go test ./<rule>/`.
- Fallow owns architecture: zones and allowed imports in `.fallowrc.jsonc`, runtime import and side-effect bans in `.fallow/rules/runtime-boundaries.jsonc`. `bun run fallow` also gates unused code (default and production passes), duplication and health.
- `bun run check` runs everything; prek runs it on commit and push.
- Disable a rule on the affected line only, with a reason. Unused disables fail lint.
